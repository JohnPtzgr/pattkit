# parsekit

Универсальный парсер «исходник + грамматика → AST»: двухпроходный лексер, восходящее
переписывание списка токенов по слоям, таблица имён, таблица операторов и отдельный слой
восстановления после ошибок. Только стандартная библиотека Python 3.9+.

```
текст ─► Pass 1 (грубые куски) ─► Pass 2 (контекст: комментарии, строки, f-строки,
                                  числа, операторы, скобки, NEWLINE/INDENT/DEDENT)
      ─► слои переписывания ─► один корневой токен = AST
      ─► (если не свернулось) слой восстановления: шаблоны ошибок + поиск правок
```

## Быстрый старт

```python
from parsekit import Parser, sexp
from examples.json_parser import make_parser, to_python

p = make_parser()
print(to_python(p.parse('{"a": [1, 2.5, -3], "b": null}')))
p.parse("[1 2]")        # ParseError: ... possible fixes: 1. insert ',' after '1' ...
```

Своя грамматика: `Parser(grammar_text, "start_rule", lexer=None)`. Лексер по умолчанию двухпроходный,
с токенами `_` между несмежными токенами (шаблоны могут писать `_` и `!_`).
`parse()` возвращает AST или бросает `ParseError` (с `.diagnostic`); `parse_recover()` возвращает
`(ast, diagnostic)`, где AST построен по исправленным токенам, если правка найдена.

## Лексер (`parsekit/lexer.py`)

Следует спецификации: pass 1 контекстно-свободен и разбивает текст без пропусков; pass 2 даёт смысл
(вложенные `/. .../`, `///`, строки с префиксами `r f rf fr` и `#`-ограждением, f-строки плоской
последовательностью `FSTRING_*`, `${ }` с вложенностью, символы `'a'`, числа `0xFF 1.5e3 t.0.1`,
операторы «самый длинный первым», фиксированная ширина отступа, продолжение строки по `,` и `\`).

| `LexConfig` | Смысл |
|---|---|
| `layout=False` | свободный синтаксис: нет `NEWLINE/INDENT/DEDENT`; переводы строк видны в `_` (`nl`, `w`) |
| `brackets="lenient"` | несбалансированные скобки не ошибка лексера: баланс проверяют ПСП-шаблоны, а пропущенная скобка доходит до слоя восстановления. По умолчанию `"strict"` (по спецификации `BRACKET_FAIL`); `Parser` по умолчанию использует `lenient` |
| `space_tokens=True` | токен `_` с текстом зазора между соседними настоящими токенами |
| `comments="trivia"` | комментарии в `.trivia` следующего токена |
| `operators`, `keywords`, `rename` | расширение таблиц, переименование типов (`{"IDENTIFIER": "ID"}`) |

## Язык грамматики

Полный список элементов шаблона и директив в докстринге `parsekit/engine.py`. Кратко:

| Запись | Значение |
|---|---|
| `NAME`, `NAME/label`, `"text"` | токен по типу/классу, по метке, по тексту листа |
| `_`, `_{nl}`, `_{w=n}`, `!_` | пробельный токен и условия; в нестрогих слоях между элементами неявно стоит `_?` |
| `A B`, `A\|B`, `A* A+ A? A*? A+?`, `X{n}`, `X % S` | последовательность, выбор, повторы (жадные/ленивые), ровно n раз, список через разделитель |
| `*`, `+`, `*?`, `+?`, `*{kind = T}` | подстановка: любые токены, срез должен свернуться в `T` |
| `<OPEN … CLOSE>` | парная скобка (OPEN/CLOSE допускают альтернативы); внутри сворачивается изолированно |
| `name=elem`, `name=ID as CLASS` | захват; захват, объявляющий имя в текущем скоупе |
| `operators E over …` | `left right nonassoc prefix postfix chain apply`, уровни от слабого к сильному |
| `names`, `unknown`, `stops` | классифицируемые типы, класс необъявленных имён, токены-границы подстановок |
| `recover:` | `имя: шаблон => "сообщение {захват}"` |

Примеры: `examples/json_parser.py`, `examples/clike.py` (typedef, `T * x`, generics),
`examples/pylike.py` (блоки по отступам).

## Как это работает

* **Слои** применяются по порядку, каждый до неподвижной точки; внутри слоя берётся самое длинное
  совпадение (при равенстве раньше записанное правило), для вложенного выбора первый успех.
* **Захват с целью и ПСП** сворачивают срез отдельным запуском через **все** слои с дочерним скоупом.
* **Таблица имён**: `as CLASS` пишет в скоуп; запись применяется на границе слоя и переклассифицирует
  токены `names`-типов, так что `T * x` и `List<int>` решаются классом токена, без отката.
* **Повторы** идут через явный стек (нет лимита рекурсии), захваты/потребление в персистентных списках.

## Восстановление после ошибок (`parsekit/recover.py`)

1. Ручные шаблоны из `recover:`: сопоставляются с тем, что осталось после свёртки; побеждает самое
   левое совпадение. В сообщении доступны `{захват}`, `{захват.line}`, `{line}`, `{col}`, `{text}`, `{found}`.
2. Поиск правок: до 2 вставок/замен токенов (удаление включается `ops=`) около места сбоя; лучевой отбор,
   бюджеты по числу проб и по времени. Порядок подсказок: меньше правок, затем токены, уже встречавшиеся
   во входе, затем правее (как заметил бы LR-парсер). Настройки: `Parser(..., window=, beam=, max_edits=, budget=)`.

`Parser.warnings` (или `parser.lint()`): неизвестные имена токенов и правил, литералы, которые лексер
не может выдать одним токеном (например `"**"` без такого оператора), неиспользуемые правила.

## Что нужно знать (ловушки и пределы)

* **Порядок слоёв важен для скоупов**: блок, вводящий скоуп (`<"{" … "}">`), должен идти в слое раньше
  объявлений, иначе слой объявлений увидит `typedef` внутри ещё не свёрнутых скобок и запишет его наружу.
* Тело захвата проходит через все слои, поэтому оно может свернуться в токен самого верхнего правила.
* Скелет шаблона сопоставляется перебором с возвратом, а **не** двумя ДКА. Скорость на тестах линейная
  (32000 элементов JSON ≈ 3 с, 1600 операторов C-подобного кода ≈ 0,2 с), но константа питоновская.
* Подстановка `*` без `kind` и без `stops` может на длинном входе перебирать O(n) вариантов.
* Поиск правок стоит одного полного разбора на пробу: для больших файлов ограничивайте `budget`.
* Ошибки лексера (кроме скобок в `lenient`) останавливают лексинг на первой: `LexError` с кодом из спецификации.
* Нет mixfix (`?:`) в таблице операторов: записывается обычным правилом между уровнями.
